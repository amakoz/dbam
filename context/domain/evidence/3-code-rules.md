# Evidence: rules guarded in the code

Scope: the whole repository at head 74c2d16 (single application), minus the paths that `context/domain/evidence/0-sources.md` excludes. No domain documents were read.

Layers searched:

- **Database.** All 13 migrations in `supabase/migrations/`. Only the header and the upsert tail of the generated `*_screening_catalog_snapshot.sql` files were read, because the rest is catalog data.
- **Data-set validator.** `src/lib/catalog/schema.ts`, `scripts/catalog/{check,migration,lib,draft-core}.ts`.
- **Entry points.** `src/middleware.ts`, every `src/pages/api/**/*.ts`, the frontmatter of `src/pages/*.astro`, `src/worker.ts`, `wrangler.jsonc`.
- **Logic.** `src/lib/**`, including `src/lib/reminders/`, `src/lib/screenings/` and `src/lib/catalog/`.
- **UI.** `src/components/**`, except the vendored `ui/` folder.
- **Tests.** Assertion names in `supabase/tests/database/*.test.sql`, `src/**/*.test.ts` and `tests/e2e/*.spec.ts`.

Search patterns:

- SQL: `check`, `unique`, `references`, `policy`, `grant`/`revoke`, `security definer`, `raise exception` and `trigger`.
- Code: `throw`, `return fail(`, `redirect(` with `?error=`, `if (!…) return`, and the `error.code` comparisons.
- UI: the `min=`, `max=`, `required`, `disabled` and `hidden` attributes, and conditional rendering.

Not covered:

- `src/i18n/*` copy, which is outside this brief.
- Supabase Auth settings (`supabase/config.toml` and the production dashboard), apart from the password check mirrored in `src/lib/password.ts`.
- Supabase's default role privileges and the PostgREST exposure of the publishable key (see Unknowns).

Labels: **E** = evidence (read and cited in this session), **I** = inference, **U** = unknown.

## Writers that work against a guard

- **Different "current year" by path (E/I).** The SSR paths compute age from the runtime's local year: `now.getFullYear()` in `src/pages/dashboard.astro:53` and `src/pages/api/screenings.ts:130`, and `new Date().getFullYear()` in `src/pages/api/profile.ts:35`. The cron uses the Warsaw year: "Eligibility uses the Warsaw year, not the runtime's local one", `src/lib/screenings/due.ts:32,35` (Vitest `due.test.ts:147-160`). The `screenings.ts:122-123` comment claims that "The year matches the dashboard's", and that holds between those two SSR paths. Around the Warsaw New Year (UTC 23:00–24:00 on 31 Dec) the cron and the dashboard can disagree on tier membership. Inference: the Workers runtime TZ is assumed to be UTC, which was not verified here.
- **Appointment reminders ignore catalog status (E).** `claim_due_appointment_reminders` never joins `screening_catalog` (`20260930125726…:99-133`). The follow-up nudges require `c.status = 'active'` (`20261006204148…:82,95,127`) and the due-screening functions require `s.status = 'active' and s.interval_kind = 'fixed'` (`20261006155313…:124,185,214`). A plan on an entry retired after planning still gets an appointment email. That plan cannot be confirmed (pgTAP `screening_confirm.test.sql:246`) and gets no confirm nudge. A search of `appointment_reminders.test.sql` for "retired" and "draft" found no case.
- **The UI offers actions the server will refuse (E/I).** `PlanItem.astro:70-78` always renders the re-plan form (`ScreeningActions`), including for a plan whose `tier` is `null` (no longer recommended) or whose entry is retired. `POST /api/screenings` then answers `screening_not_available` (`screenings.ts:131-133`) or fails RLS.
- **Direct profile delete without withdrawal (E/I).** The policy "Users delete their own profile" (`20260927190303…:119-121`) lets a client delete the profile while the consent stays active. No app path does this: a search of `src/` for `from("profiles").delete` found none. The user then drops back to `needs_profile` (`src/lib/consent.ts:39`).
- **The catalog snapshot overwrites status in place (E).** `on conflict (slug) do update set status = excluded.status` (`20260929165522…:529-530`). A search of `scripts/catalog/*.ts` and `src/lib/catalog/schema.ts` found no guard on status transitions (for example active → draft). An entry moved back to draft would disappear from `getCatalogEntries` (`read.ts:50`, active/retired only). Users' plans and done records on it would then be skipped silently on the dashboard (`rules.ts:249,274`).
- **The heartbeat's `PROVING_CRON` has a handler but no trigger (E).** `"*/30 * * * *"` is handled at `src/lib/schedule.ts:6` and `src/lib/heartbeat.ts:60-61`. `wrangler.jsonc` declares only `"0 8,9 * * *"`. This is operational, not a business rule.

## Failure handling

- **Named errors:**
  - `?error=<code>` redirects: `invalid_request`, `consent_required`, `consent_outdated`, `invalid_profile`, `invalid_appointment_date`, `invalid_done_date`, `screening_not_available`, `appointment_not_passed`, `withdraw_confirm_required`, `weak_password` (`src/pages/api/**`).
  - Codes are translated via `errorMessageKey`, and unknown codes become `errors.unknown` (`src/lib/errors.ts:6-10`).
  - DB results: SQLSTATE 42501 (RLS or not authenticated), 23505, 23514 and 22023 ("invalid reminder window or limit", `20260930125726…:93-97`; "invalid date or items", `20261006155313…:172-176`; "invalid nudge threshold or limit", `20261006204148…:71-76`).
- **Generic errors:**
  - Most DB write failures become `save_failed`, `reminders_failed` or `withdraw_failed`, with no code passed on (`screenings.ts:69,144,156,163`; `profile.ts:42-43`; `reminders.ts:34-35`; `withdraw.ts:28-29`).
  - SSR read failures throw `DatabaseError` (code only), which renders the 500 page (`src/lib/database-error.ts:5-16`, `src/lib/screenings/read.ts:19-20`).
  - Cron failures throw `ReminderDatabaseError(step, code)` (`src/lib/reminders/errors.ts:4-13`).
- **Logs and continues:**
  - Invalid catalog rows are hidden with only a log line (`src/lib/catalog/read.ts:22-24,67-69`).
  - A failed reminder job is logged and alerted, and the later jobs then get budget 0 (`src/lib/reminders/chain.ts:36-65`).
  - A failed failure-alert email is logged only (`src/lib/failure-alert.ts:35-47`), and with no recipient it logs `skipped` (`:21-25`).
- **Swallowed silently:**
  - A duplicate consent (`23505`) is treated as success (`grant.ts:31`).
  - Sign-out ignores the result of `supabase.auth.signOut()` (`src/pages/api/auth/signout.ts:7`).
  - A failed code exchange redirects to `?confirmed=1`, which is not an error page (`src/pages/api/auth/callback.ts:24-28`; the reason is given at `:25-26`).
  - Confirm `not_found` redirects with no message ("a double submit … or a stale page", `screenings.ts:93-96`).
- **Silently corrects:**
  - Smoking fields that don't apply are nulled (`profile.ts:68`).
  - `reminders_enabled_at` is server-stamped (`20260930125726…:21-37`).
  - A stale `last_done_on` is cleared (`20261005180420…:12-24`).
  - Drafts are forced to `draft` (`draft-core.ts:280-281`).
  - A fixed entry without months is treated as `no_known_interval` (`recommend.ts:91-92`).
